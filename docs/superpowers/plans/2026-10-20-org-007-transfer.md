# ORG-007 Project Transfer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Complete the ORG-007 browser vertical slice for reviewed, planning-only project import/export without changing the existing transfer API contract.

**Architecture:** Keep serialization, fingerprinting, validation, limits, and cycle detection in the existing API transfer service. Extend the feature-owned transfer page to expose parse/preview/commit states and explicit stale/invalid errors; use the public API client only for transport. Preserve the existing export evidence and planning-only truth boundary.

**Tech Stack:** React 19, TypeScript, Vitest/Testing Library, Playwright Chromium, FastAPI/Pydantic, SQLite.

**Spec:** `docs/specs/ORG-007-transfer/spec.md` and `docs/specs/ORG-007-transfer/acceptance.md`

## Global Constraints

- Transfer uses the versioned `forge-project-import-v1` JSON contract.
- Preview computes a canonical fingerprint without writing.
- Commit requires the exact reviewed fingerprint and writes planning records only.
- Runs, decisions, evidence, context packages, and release records remain excluded.
- Do not weaken API limits, stale-fingerprint rejection, cycle validation, or architecture boundaries.
- Do not begin ORG-008 desktop packaging or Stage 1.

## Review Focus

- Valid exported document: preview shows counts/fingerprint and enables reviewed commit.
- Invalid JSON or wrong schema: page shows an accessible error and does not call import.
- Edited document after preview: API rejects stale fingerprint and page preserves the error.
- Successful commit: page shows `IMPORTED_PLANNING_ONLY` and created project identity.
- Existing browser screenshots: transfer evidence remains representative desktop/mobile and no unrelated baselines are regenerated.
