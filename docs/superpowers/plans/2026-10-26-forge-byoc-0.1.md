# FORGE BYOC 0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add safe user-owned Supabase storage for the first Workspace/Project/Epic/Story vertical slice while preserving local SQLite behavior.

**Architecture:** Keep the existing same-origin transport for local SQLite and add a runtime-configurable Supabase Auth/Data API adapter in `@forge-org/api-client`. Use owner-run SQL with RLS and narrowly scoped functions; do not turn the local sidecar into a privileged proxy.

**Tech Stack:** TypeScript, React/Vite, existing `@forge-org/api-client`, FastAPI/Python profile contracts, Supabase Auth/Data API over `fetch`, PostgreSQL SQL/RLS, Tauri 2 CSP.

**Spec:** `docs/superpowers/specs/2026-10-26-forge-byoc-0.1-design.md`

## Global Constraints

- Local SQLite remains the default and existing local routes/imports/exports remain unchanged.
- Supabase accepts only a project URL and `sb_publishable_*`; no secret/service-role/database credentials.
- The installed client uses HTTPS Data API + user JWT, never a PostgreSQL connection.
- The owner explicitly applies provisioning SQL; FORGE never provisions a real project.
- No silent SQLite fallback, data transfer, production DB access, main-branch mutation, or automatic merge.

## Review Focus

- A privileged key, malformed URL, query/fragment, userinfo, or SSRF host is rejected without echoing the credential; profile tests pin this to the API-client and Python contracts.
- An expired, missing, or invalid JWT produces an authentication state/error and never activates local storage; auth/transport tests pin this to the storage manager.
- Missing schema, wrong schema version, denied RPC, and outage never report `ready`; preflight tests pin this to the remote adapter.
- A user without workspace membership cannot list or mutate another workspace; SQL policy tests and mocked cross-workspace Data API tests pin this to provisioning/adapter tasks.
- Existing local mode and transfer/import/export paths continue using SQLite and do not inherit cloud configuration; existing suite plus transport regression tests pin this to the compatibility task.
