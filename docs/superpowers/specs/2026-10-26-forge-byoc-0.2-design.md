# FORGE BYOC 0.2 Design

## Intent

Extend the existing owner-managed Supabase adapter from the BYOC 0.1 vertical
slice to functional parity with the active SQLite planning and transfer
capabilities. The installed application remains unprivileged: React calls
`@forge-org/api-client`, which calls either FastAPI/SQLite or Supabase Auth,
Data API, and Storage. FORGE never receives a PostgreSQL connection string or
an owner/service-role credential.

## Decisions

- Keep `organizationApi` and every existing capability signature stable.
- Add the missing Supabase tables, private storage bucket, RLS policies,
  grants, constraints, and transaction RPCs in incremental owner-run
  migrations. `20261026_byoc_0001.sql` is already applied and is immutable.
- Use narrow REST table operations for simple reads/writes and RPCs for
  reorder, dependency validation, and multi-record transfer commits.
- Store attachment bytes only in the private `forge-bug-attachments` bucket;
  store trusted metadata in a relational table and expose content through an
  authenticated Storage request, never a public URL.
- Keep JSON and ZIP transfer validation in the client-side adapter aligned with
  the existing versioned SQLite contract. Remote commits are single RPC calls
  with staged attachment cleanup on failure.
- No silent local fallback, automatic provisioning, real-project access, or
  offline/realtime synchronization.

## Trust boundary

The browser/WebView holds only a publishable key and the signed-in user's JWT.
Every table and RPC is protected by membership-aware RLS and explicit grants.
Composite foreign keys prevent records from crossing projects, while owner-run
functions enforce atomic reorder, dependency cycle checks, and transfer
transactions.

## Verification boundary

Contract tests use mocked Supabase HTTP responses and migration static checks.
If Supabase CLI/Docker is available, migration tests run against a disposable
local Postgres/Supabase instance. A real user project is never accessed by the
test suite; real-project A/B/C validation remains a documented owner action.
